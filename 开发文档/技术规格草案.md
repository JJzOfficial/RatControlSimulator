## 1. P0闭环范围与排除项

### 1.1 闭环与交付顺序

P0主线为：新档公司整备 → 接Q01 → 出发装车 → L01白天固定本局种子与3个目标票据，不生成鼠实体 → 处理两处虫源及一处漏水（可夜间补） → 可选封缝/布防 → 主动入夜并在室外隐蔽节点固定激活5只M01 → 全部控制（全封时在室外捕捉） → 目标暂达成 → 调查/转移/回收/装车 → 离场复核 → 合同结算 → 收购商出售或动物园捐赠 → 重玩或读回同一委托。

建议拆为可验收增量，避免同时并行制作所有内容：

1. `P0-A`：一个室外夜间激活点、一只M01测试票据、固定节点、击杀与尸体调查；不做复杂角色动画。正式Q01始终使用5只。
2. `P0-B`：匹配小笼、容器占用、4格携带、固定车辆、尸体袋和活体转舱；通过实体守恒验证。
3. `P0-C`：L01/Q01昼夜、两虫源/一漏水、有限总量5只M01、三项挑战、离场/结算/重玩。
4. `P0-D`：出售、捐赠、释放再捕、手动存档/自动存档、失败恢复、订单与交易防重复。
5. `P0-E`：I01/I05代表标本、M02行为测试、Q01后C01重访路径、吹箭/长矛/气枪瞄准与屏息测试；正式商店进度不变。
6. `P1伙伴增量`：在P0链条稳定后，先一只猫两模式，再狗，最后双伙伴与静默冲突。不是P0首轮前置。

## 2. 最小架构、所有权与执行顺序

### 2.1 七个模块

| 模块 | 唯一拥有的数据与职责 | 不应负责 |
| --- | --- | --- |
| `RunFlow` | 当前委托、阶段、有效游戏时钟、暂停原因、场景装载和离场确认流程 | 直接增减钱、删除动物或推算库存 |
| `CreatureSimulation` | 动物生命周期、感知、行为、路径、暂时控制、伙伴命令与目标占用 | 发合同奖励、直接创建可售库存 |
| `InteractionTools` | 交互候选/优先级、持续交互、工具使用、弹药、部署/复位请求 | 自己给任务加计数、直接改图鉴 |
| `CargoLogistics` | 所有物品实例、容器、位置归属、背包/车位容量、转移/装车、订单 | 推导合同是否成功、生成经济奖励 |
| `SiteObjectives` | 虫源/修复/封堵/财产、合同条件与挑战投影、生成预算、进度与失败理由 | 根据动画事件直接增删钱或星 |
| `ProgressionEconomy` | 现金、经验、技能、解锁、图鉴、交易及奖励账本、报价 | 接管动物AI或现场路径 |
| `PresentationPersistence` | HUD/面板/本地化、存档序列化与迁移、输入到命令的适配 | 在View中保存权威运行状态；存档不自行补发事件奖励 |

`PresentationPersistence`在工程目录内仍可分UI与Persistence两个子目录；合并只表示原型不引入额外框架。权威领域规则优先纯C#，薄MonoBehaviour负责Transform、Collider、Animator和场景绑定。静态配置用ScriptableObject或等价数据资产，运行状态不回写配置。

### 2.2 Bootstrap与场景

- 一个Bootstrap显式依序初始化：配置校验 → 存档读取/迁移 → 领域实例 → 场景绑定 → 事件订阅 → 恢复运行；未完成初始化禁止输入与AI Tick。
- 场景建议为公司、L01、独立测试场；昼夜优先在同一L01状态中切换，保留实体与通路，而非重载一份夜晚场景丢掉准备成果。
- 加载存档先建全部实体字典，再恢复容器和伙伴引用、通路占用、计时器，最后恢复表现；不依赖MonoBehaviour的Awake顺序。
- 只有Flow推进有效游戏时间。暂停面板、存档快照、恢复期间，AI、短控、物流、挑战计时和Q冷却都不推进。
- UI是否暂停必须由统一的 `PausePolicy` 决定。详细合同/背包/图鉴/伙伴轮盘暂停；车辆快速取物不暂停；车辆完整仓库暂停为策划建议，冻结时明确。

### 2.3 权威命令与领域事件

写操作走命令，读取用只读查询或快照。事件是已成功提交的结果，订阅者不得把同一事件再次当作请求执行。P0无需全局反射事件总线或完整事件溯源框架。

命令通用字段：

`commandId: Guid`、`runId: Guid?`、`actorId: EntityId`、`targetId: EntityId`、`expectedRevision: int`、`requestedAtTick: long`、`payload`。

统一返回：

`status: Accepted|Rejected|AlreadyApplied`、`reasonCode`、`newRevision`、`readBack`、`emittedEventIds[]`。重复 `commandId` 返回原结果；过期版本返回 `STATE_CHANGED` 并给出当前可用动作。

事件通用字段：

`eventId`、`sequence`、`runId`、`tick`、`entityId`、`sourceActorId`、`sourceToolId?`、`sourceKind: Player|Cat|Dog|Trap|Environment|System`、`causeCommandId`、`beforeRevision`、`afterRevision`、`payload`。

| 命令/接口草案 | 前置与权威拥有者 | 成功事件/主要订阅者 |
| --- | --- | --- |
| `AcceptContract(contractId, loadout, companions)` | 公司阶段、已解锁、出勤名单合法；Flow | `ContractAccepted` → 场景、生成、UI |
| `BeginNight(runId)` | 白天阶段、显示摘要并确认；Flow | `NightStarted` → 时钟/生成阶段/挑战快照/自动存档 |
| `StartInteraction(actionId, targetId)` / `CancelInteraction(token)` | 交互可用、范围/视线/工具/容量合法；Interaction | `InteractionStarted/Cancelled` → 仅表现，不给奖励 |
| `CommitWork(siteId, actionToken)` | 材料与作业状态再校验；Site+Inventory同事务 | `WorkCompleted`、`RouteChanged`、`SampleCreated` |
| `TryApplyEffect(targetId, effect, hitContext)` | 当前状态与工具适配；Creature | `CreatureKilled/ShortControlled`，拒绝时反馈适配原因 |
| `TryCapture(targetId, containerId, actionToken)` | 动物活着、容器空且匹配、路径/交互有效；Creature+Cargo | `CaptureCommitted` → 合同投影、捕获统计、稀有保底 |
| `TryTransfer(entityId, sourceLocation, destLocation)` | 实体来源版本匹配、容量已预留；Cargo | `CargoTransferred`，不重复触发独立个体捕获数 |
| `Investigate(entityIdOrSampleId, token)` | 满足物种调查路径；Progression | `InvestigationCompleted/CodexUnlocked`；普通活体返回明确不适配 |
| `LoadAnimalToVehicle(animalId, vehicleSlotId)` | 空车位、合法动物货物；Cargo | `VehicleLoaded`、`PortableContainerReturned` → 活捉装车星 |
| `ReleaseAnimal(animalId, releasePoint)` | 无终结交易、明确确认；Creature+Cargo | `AnimalReleased` → 合同撤销控制、原ID恢复活动 |
| `HandoverToEmployer(animalId, handoverId)` | 稳定控制、合同接受；Cargo+Objectives | `EntityFinalized(reason)` → 任务计数保留，禁止交易 |
| `RequestDeparture` / `CommitDeparture(confirmToken)` | 显示遗留清单；最终重新验证；Flow | `RunFinalized` → 唯一合同结算、场景卸载 |
| `TradeEntities(entityIds, Sell\|Donate)` | 公司、每只合法、报价版本确认；Economy+Cargo | 每只 `TradeCommitted`；批量逐只结果并回显收益 |
| `PlaceOrder(itemId, count)` / `DeliverOrder(orderId)` | 余额、禁运类别、订单状态合法；Economy+Cargo | `OrderPaid/Delivered/Rerouted`，重复抵达不发第二份 |
| `SetCompanionCommand` / `SetCatMode` | 出勤、指令合法；Creature | `CommandChanged`；涉及放开活鼠须独立确认 |

合同计数必须从实体处置状态和合同规则计算，不能靠收到一次“抓住”事件就永久加1。事件用于增量更新，加载后可从快照重建同样进度。

### 2.4 同帧处理与原子边界提案

固定领域Tick建议顺序：输入/工具命令入队 → 命中/捕获/转移命令共同按稳定序列提交 → AI刺激与行为决策 → 路径/移动结果 → 财产作业结算 → 合同/挑战投影 → 唯一离场/经济结算 → 保存快照。命中与捕获不分别批量先后执行，避免绕过ENG01。渲染/动画事件不得独立增减权威物品。

工程默认ENG01按稳定命令序列号处理同帧命中与捕获。一个实体只能有一个权威结果，不能同时成为活体车货和可售尸体。持续动作完成前重校验生命、范围、容器与容量；预览校验不代替提交校验。对同一Tick收集到的不同来源命令使用固定排序，避免依赖MonoBehaviour更新先后。

| --- | --- | --- |
| `CompanyPreparing` | 接单、购买、技能重置、装车、选伙伴、交易/调查 | 接单确认后生成runId，出发前自动存档 |
| `DayArrival` | 展示合同、固定本次种子/预算/身份、场景初始化 | 初始化完成进DayWork；不在读档时重抽 |
| `DayWork` | 无限准备、必做/可选作业、部署/移位/换装 | 未完成必做不阻入夜，摘要明确可夜间补；主动确认后不可回白天 |
| `NightWork` | 搜索、工具、回车、控制、调查、回收 | 主目标满足转ProvisionalComplete；硬失败立即FailureFinalizing并自动结束现场 |
| `ProvisionalComplete` | 继续调查/回收/捕获/释放 | 不刷新新预算；释放目标可退NightWork；保护责任尚未结束不能直接跳过 |
| `DepartureReview` | 查看遗留、回现场、确认接管或释放 | 输入与世界按统一面板暂停规则；确认前重新计算主目标和控制归属 |
| `Finalizing` | 只允许状态提交/保存，禁重复交互 | 一次性确定成功/失败、新星与奖励；成功后CompanySettlement |
| `FailureFinalizing` | 冻结现场，展示失败/救援原因，只允许结算保存 | 自动返回公司；丢动物货物，保永久设备/个人物资；不给继续回收窗口 |
| `CompanySettlement` | 展示唯一结算结果、出售/捐赠/调查 | 已结算runId重开界面只读；完成后回CompanyPreparing |

`Paused`不是新的委托阶段，是带原因栈的时间门控；不能因开关菜单触发阶段Enter重复奖励。`ProtectionFinished`建议作为时间条件快照，锁定结束时财产比率，但附带指定动物仍可尚未处理。搜索/除巢允许`AbortFinalizing`，不发合同奖/新星但保留已装车动物货物；保护/限时未完成时主动终止进入失败分支并丢动物货物。正常履约完成后的离场不是主动终止。

### 3.2 生物状态采用正交字段

避免一个巨型枚举同时表达“已调查、车内、短控、任务达成”。建议每只动物至少分为：

- `life: Alive|Dead`，死亡后不可复活；尸体仍用原 `entityId`。
- `custody: Free|ShortControlled|CatHeld|PortableContained|VehicleContained|EmployerAccepted|Finalized`。
- `behavior: Activity|Notice|Alert|Flee|Hide|Recover|ApproachAsset|Threat`，仅在实际已生成、未稳定受控且活着时推进；未生成预算不是鼠实体。
- `discovery: Unknown|Discovered`，`investigation: None|Completed`，物种图鉴另属于永久账本。
- `terminalReason: None|SoldAlive|DonatedAlive|SoldCorpse|ContractDelivered|EmployerAccepted|DiscardedCorpse|AllowedDrivenOut|CompanyReleased|LostOnFailure`。
- `location`为互斥归属：World、PlayerSlot、PlayerHands、PortableContainer、VehicleSlot、CompanyStock、EmployerPoint、Terminal；不能同时存在两个所有者。

`ShortControlled`和`CatHeld`都是临时约束，暂停损害但不计稳定控制。`PortableContained/VehicleContained`须有有效容器或固定设施引用。死亡时清除临时控制和目标占用，生成可调查尸体表现，不生成另一只动物。

### 3.3 捕获—调查—转移—装车—去向

| 操作 | 提交条件 | 一次原子修改 | 不应发生 |
| --- | --- | --- | --- |
| 短控命中 | 工具支持、目标活着、效应可用 | 改临时状态与剩余时间 | 不加合同控制/库存/捕获独立个体计数 |
| 猫按住 | 目标合法、猫持有租约、扑击成功 | `CatHeld`、停止损害、保留原ID、待接手提示 | 不能免费入包/装车/售卖 |
| 稳定捕获 | 空容器匹配、活体、动作完成、容量合法 | 目标变Contained、容器绑定、来源占用解除、一次捕获事件 | 容器空状态与动物货物不能并存 |
| 调查 | 近距约2秒完成且路径适配 | 记录该实体调查；必要时解锁物种 | 普通活体不能补尸体图鉴；稀有尸体不能补活捕图鉴 |
| 容器间转移 | 源确实持有、目的已预留、动作未取消 | 同时清源/占目的/改location；空容器按规则返还 | 中途失败不能先清源丢失目标 |
| 装车 | 固定车位空、尺寸匹配 | 动物入车固定笼，原便携笼变空；入包或车仓 | 售捐时不得再返第二只空笼 |
| 尸体装袋 | 原ID已Dead、P09存在 | 消耗一个空袋实例并转成同ID尸体货物绑定；占一次容量 | 不同时扣两格，不因开袋/重封复制袋 |
| 释放 | 可释放、终结状态为空、玩家明确确认 | 脱离容器、恢复原ID到合法点；撤销未锁合同控制 | 无钱、经验、额外独立捕获数；不能释放到碰撞体内 |
| 公司释放 | 公司货物、非指定交付、玩家明确确认 | `CompanyReleased`移出世界，不给收益，保留已调查图鉴 | 不生成跨局再捕副本，不退第二只空笼 |
| 雇主接管 | 普通对象稳定控制、合同允许、交接位合法 | 记录接管并终结归属，确认后不可撤回，空容器正常返还 | 不产生售捐收益，不随工具回收再带回 |
| 活体售卖/捐赠 | 公司合法货物、非指定交付、未终结 | 锁定最终去向、移出库存、写唯一账本、给对应一种收益 | 不重复给钱/经验；不再回收空笼 |
| 尸体售卖 | 袋装、合法公司货物、未终结 | 金额=`floor(该物种该档活体报价*0.25)`并终结 | 不能捐赠、不能从已售尸体再变出活体 |

调查和装车可有不同顺序：策划允许装袋后调查袋内尸体、公司交易前调查，因此不能把“捕获→调查→装车”硬编码为唯一线路。每一步只校验自己的前置；UI优先推荐先调查。未知身份不自动因Q轮廓而调查完成。

### 3.4 必须保持的守恒与幂等不变量

1. 每个 `entityId` 在世界、容器、背包、车辆、公司、终结状态之间恰好有一个归属。尸体沿用ID。
2. 一只可交易活体最多有一个最终交易/交付终结记录。账本唯一键建议 `(profileId, entityId, settlementKind)`，另有实体“任何终结”唯一约束。
3. 每个 `runId` 最多有一个合同结算记录；每个 `(contractId, starId)`最多有一次首次星奖励。
4. 独立击杀数、独立捕获数按物种+实体集合计；再捕操作可另计，但不产生奖励。
5. 物品实例总量守恒：购买/配发是可追踪来源；消耗/出售/归还借用是可追踪出口；转移不增减。
6. 背包槽数、容器位、车位和部署上限从配置与技能推导，不保存另一份可任意增减的“已用格计数”。
7. 目标暂达成是动态条件；离场前释放任务目标必须退回进行中。离场确认令牌基于状态版本，发生变化后失效并重建摘要。
8. 存档不重放经济事件；恢复只恢复已提交状态。交易原子提交后再刷新面板，不能先加钱再等待销毁对象。
9. 批量交易逐只输出Accepted/Rejected及汇总；一次点击重试使用同一批命令ID。无合法项时不付款、不销毁物品。
10. 保存请求在领域事务之间取一致快照；不能保存“清源完成但目的容器未占用”的中间步骤。
11. 失败/救援终结时动物货物统一标`LostOnFailure`，不给售捐收益；永久便携容器保留原实例并清空。已消费的尸体袋不凭空退回。主动终止始终明确显示货物结果：搜索/除巢保留已装车货物，未完成保护/限时进入失败并丢动物货物。

### 3.5 持续交互取消

开始时检查目标、距离、视线、工具与最低资源；完成时再次检查并原子扣资源。主动取消、离开范围、失去视线、换工具、死亡、目标状态改变或暂停策略切换均给出明确结果。

提案：完成前取消不消耗材料/袋/诱饵，不累计可反复刷的部分收益；调查取消进度归零，已完成记录永久保留。短控时间暂停规则由有效游戏时钟统一。转移中断保留源占用，目的预留释放，不把动物放到中间位置。

### 3.6 Q01固定激活与计数

| 时点 | 权威状态 | 不变量 |
| --- | --- | --- |
| 白天到场 | 固定runId、seed、5个`spawnTicketId`及室外候选节点，尚无鼠实体 | 场景与Q扫描均无鼠；票据不是可调查或可捕获对象 |
| 入夜确认 | 暂停输入，在夜间过渡期间原子创建5个固定`entityId`并绑定票据；然后开启夜间有效时钟 | 推荐短淡入/既有遮挡确保不可见激活；五只均成功才提交NightStarted和自动档 |
| 激活失败 | 整批回退，保留白天世界/票据并报告缺节点或资源 | 重试沿用同ID，不创建第6只；不带着不足5只进入正式夜晚 |
| 夜间活动 | 五只可尝试室外/入室路线；封堵边失效，全部封好时仍有室外路线 | 全局补充数0；死亡/捕获/躲藏/释放都不补新鼠 |
| 主目标计算 | 按5个实际实体ID计算`Dead OR StableContained OR EmployerAccepted` | 临时短控、猫按住、逃出视野、封堵、普通受惊逃跑都不计数 |
| 现场释放 | 原ID恢复自由；若尚未离场锁定成功，从已处理集合移除 | 允许再捕，无额外现金/经验或独立个体统计 |
| 暂达成/离场 | 五只均已处理、两源一漏已完成、家具≥60%后暂达成；离场再复核 | 家具一旦低于60%立即失败；80%恰好达保护星；封缝星取入夜时快照 |

固定动物并不要求随机性消失：可按seed在已验证的室外节点集合中选择起始点，但数量、身份和生成时点不变，读档不重抽。所有激活点都须提供室外停留、藏匿和笼捕可达路径，不能用封堵后穿墙或传送保持任务可做。

| 结束原因 | 触发 | 合同奖/本局新星 | 已装车动物货物 | 永久设备/个人物资 | 图鉴 |
| --- | --- | --- | --- | --- | --- |
| Success | 主条件最终复核通过 | 正常唯一结算 | 保留，可出售/捐赠/公司释放 | 保留，借用按合同归还 | 已调查保留 |

| ContractFailure | 家具低于60%等公开硬失败，自动结束现场 | 不发 | 丢失，标LostOnFailure | 保留 | 已调查保留 |

离场按钮必须把“完成离场”“主动终止”“失败自动返回”分别命名并显示货物结果。失败已被提交后不能再用主动终止命令抢救已丢货物；两命令同Tick以稳定序列及失败优先规则形成一个最终结束原因。

## 4. 鼠、猫、狗AI规格草案

### 4.1 共用刺激、筛选与优先级

刺激结构：`stimulusId, kind, sourceId, position, radiusM, intensity01, emittedTick, expiresTick, requiresLineOfSight, routeReachable, targetFilter`。光束、移动声、设备声、诱饵和狗叫分类型，不能全转换成“发现玩家”。Q扫描不产生刺激。

感知先粗筛区域/距离，再做必要视线或路径校验；伙伴不能读取Q透墙列表直接捕捉。AI Tick建议近区5—10Hz、远区1—2Hz，表现插值每帧执行；是测试初值，不是已测性能。禁止每只动物每帧全场景Find或多次路径重算。

统一响应优先级提案，从高到低：

1. 已终结/死亡：停止所有AI、释放目标租约；不可被狗叫、诱饵或短控覆盖。
2. 稳定容器控制：关闭野外活动与损害；只接受合法转移/调查/终结。
3. 猫按住/其他明确持续约束：维持约束，忽略狗驱离；必须先释放才可逃跑。
4. 短控：保持到计时结束；不被诱饵直接唤醒。致死仍可中断，命中与捕获同帧定序见ENG01。
5. 合同有效狗叫/直接威胁：转入逃离，已在同一次逃离中不叠加时长。
6. 警戒阈值触发：逃向已知合法藏匿点；危险物种才使用Threat分支，M01/M02不攻击玩家。
7. 玩家/光照/声音引起留意或警觉：暂停取食、观察，再根据持续刺激升级或恢复。
8. 诱饵、取食、巡游：只在无更高优先级且路由可达时执行。

两个相同优先级刺激按危险度、距离、最近时间和稳定ID排序；使用固定迟滞/最短驻留时间，避免每Tick在诱饵与逃跑之间抖动。

### 4.2 M01/M02地表鼠状态表

| 状态 | 进入/动作 | 退出条件 | 关键限制 |
| --- | --- | --- | --- |
| `未生成预算` | 只存在票据/数量配置，不实例化鼠、Collider或可感知对象 | 夜间按冻结的生成规则创建实体→Activity | 不是生物AI状态；白天Q不能扫出待生成鼠 |
| `Activity` | 沿边节点移动、短停、走向食物/污染点 | 刺激达Notice；诱饵有效→ApproachBait；到资产→Feed | 不穿封堵边；保持可处理窗口 |
| `ApproachBait` | 沿真实路径接近已部署诱饵 | 到笼/夹有效入口→触发判定；威胁→Alert/Flee；诱饵无效→Activity | 不从墙外瞬移；诱饵不是强制抓获 |
| `Feed` | 进入资产作用点，读起手后按间隔结算损害 | 威胁/控制中断；完成动作寻下一个点 | 不在移动时连续每帧扣财产 |
| `Notice` | 抬头/停顿，积累警戒 | 阈值升高→Alert；刺激消失且低于回落阈值→Activity | 提供可射/可读窗口 |
| `Alert` | 面向刺激，准备逃跑 | 高阈值或有效狗叫→Flee；失去刺激且冷却完成→Recover | 无隔墙发现玩家 |
| `Flee` | 向合法藏匿节点或合同驱离边界移动 | 到点→Hide或DrivenOut；无路→PathRecovery | 跑远/不可见不等于已驱离 |
| `Hide` | 藏在可追踪位置，保留声音/痕迹线索 | 安全时间结束→Recover；路径再开可换出口 | 不能删最后一只；不能钻未知洞即算控制 |
| `Recover` | 警戒缓降，短时防抖 | 到低阈值→Activity；新高刺激→Flee/Alert | 驱离后可按合同规则再入保护区 |
| `ShortControlled` | 约5秒窗口提案，停止移动/损害 | 稳定捕获→Contained；窗口到→Recover/Alert；致死→Dead | 不计合同/交易库存 |
| `CatHeld` | 被指定猫暂时约束 | 玩家匹配容器交接；明确释放；猫卡路恢复 | 原ID保留，不自动调查 |
| `Contained` | 便携/车辆匹配容器稳定控制 | 转移/释放/交接/终结 | 不跑AI，不消耗诱饵/再触发陷阱 |
| `Dead` | 终止运动，尸体/装置残骸可调查 | 装袋、回收、交易/弃置 | 原ID只计一次 |

M02复用状态逻辑，以数据调整地面洞口、成对露头、速度与停留，不新增通用地下世界。鼠洞/梁节点是有向图，边包含通行体型、当前封堵状态、出口和可恢复节点。

### 4.4 猫AI与目标占用

指令态与工作态分开：`command=FollowWork|StationWork|GoTo|QuietFollow|Wait|ReturnVehicle`；`mode=LiveCapture|Kill`；`workState=Navigate|Search|Acquire|Approach|Pounce|Chase|Hold|MarkCorpse|Rest|Blocked`。

| 工作状态 | 条件与动作 | 退出/归属 |
| --- | --- | --- |
| Search | 约10—15m局部范围，视线/真实路线筛选M01—M05且身份允许 | 无目标保持指令；有目标申请租约 |
| Acquire | `TryReserve(targetId, companionId)`原子成功 | 成功→Approach，失败找下一只 |
| Approach | 走到可扑位置，不从地面瞬抓屋梁鼠 | 目标/合同失效、不可达或超时→放弃并释放租约 |
| Pounce/Chase | 有明确扑击/失手、短距离追逐 | LiveCapture成功→Hold；Kill成功→Dead/MarkCorpse；失手→Chase或Rest |
| Hold | 临时按住1只，暂停目标损害，HUD显示待接手 | 转移成功→释放租约并Rest；改变可能放开的指令需确认 |
| MarkCorpse | 猫击杀产生原ID尸体并标记 | 玩家仍需调查/袋装/装车，猫回Rest后继续局部工作 |
| Rest | 追逐后短休整 | 到时→Search；伙伴协作按最终减幅修正 |
| Blocked | 反复无路停止并提示 | 回车找回在合法非突兀位置恢复；若Hold目标，原地恢复自由并保留ID |

目标筛选硬条件：普通且本合同可干预、M01—M05、地表可达、活着、非稳定容器、非稀有/家畜/蛇/未确认非目标、未被其他猫租约占用。指定活捉对象在Kill模式下跳过并解释；LiveCapture可以协助，但仍须容器交接。

模式更改只影响后续处理；不能把已Hold活鼠直接改为Kill。Wait保留Hold并提示接手；ReturnVehicle若有Hold先要求转移或明确释放，不能把目标跟猫免费送公司。QuietFollow停主动搜捕，涉及释放规则按具体指令提示，未确认不悄悄松开。

猫参数提案：局部半径12m、追逐上限8s、离工作点上限15m、休整4s、扑击准备0.4s、目标租约检查0.5s；全部配置化。租约持有期间持续验证，猫完成/放弃/释放/死亡目标/恢复时清除；存档保存租约，恢复后验证双方引用一致。

### 4.5 狗AI、犬吠与驱离

`command`复用伙伴指令；工作态为 `Navigate|Watch|NoticeTarget|BarkWindup|Bark|Cooldown|Blocked|VehicleStandby`。不需要逐只指派，狗不追咬或造成伤害。

| 状态 | 条件与动作 | 退出 |
| --- | --- | --- |
| Watch | 跟随/定点期间自动感知普通有效威胁 | 视线/感知满足且当前可叫→NoticeTarget |
| NoticeTarget | 复核合同身份、物种、状态、噪声许可和猫占用 | 合法→BarkWindup；否则说明原因并回Watch |
| BarkWindup/Bark | 发一次有来源的噪声/驱离刺激 | 为受影响目标发 `DriveOffStarted`；进入Cooldown |
| Cooldown | 短暂再吠间隔，仍可跟随/巡查 | 到时→Watch；同次逃离不刷新驱离时长 |
| QuietFollow/Wait | 停止主动吠叫 | 玩家明确恢复工作才再叫 |
| ReturnVehicle | 回车并停止现场工作 | 可在本局再次叫出；不更换未出勤个体 |
| Blocked | 提示不可达 | 合法回车找回，不生成捕获或完成事件 |

狗硬排除：家畜、稀有、普通非目标、稳定容器、任何猫正在追逐或按住的实体。可干预对象包括本单指定有害蛇/野猪/灰狼，必须来自合同的实际许可列表。

驱离结果必须由目标到达边界节点产生：`DriveOffStarted`只代表行为启动；`DriveOffBoundaryReached`经过合同验证后才可形成已处理。要求捕杀/活捉/交付的合同使用地图内撤离节点，仍可追踪；允许场外驱离的合同才启用场外节点。未正式结算目标冷却后可重返。

狗参数提案：工作半径12m、有效犬吠半径8m、起手0.4s、再吠间隔6s、同实体驱离事件去重键 `(dogBarkId, targetId)`；狗1、狗2对同一已Flee目标不叠加时长。伙伴协作1/2级使用总减幅30%/60%，不连续相乘或减到0。

### 4.6 路径与卡路恢复

- 地表玩家/猫/狗使用工程已选寻路方案；鼠洞/梁等走专用节点图，不要求新增大型AI框架。
- 封堵提交后先失效相关边，再通知路径重算；内存中不得保留能穿封堵的旧路线。
- 无路先停止危险移动并求最近合法节点；超过超时才排队恢复，视野内不瞬移。最后一只必须有可达恢复点与线索。
- 目标恢复不能消耗/退还新的陷阱、发捕获/驱离完成或换ID；恢复日志记录原因、前后节点和实体ID，便于复现。
- 伙伴不阻挡玩家、射线和陷阱触发层；无生命值、受伤、治疗或死亡状态。

### 5.3 恢复与校验顺序

1. 检查完整性和schema；未来版本档拒绝覆盖，给出可读说明。
2. 逐版本迁移DTO；每步可测且不修改原档，保留备份。
3. 装载对应内容版本，检查ID存在及别名替换映射。配置改价不自动重复计算已提交交易。
4. 恢复静态场地与runId/seed/预算，再建全部实体索引。
5. 恢复互斥归属、容器、装置、路由、伙伴租约；校验双向引用，发现冲突停止运行并输出恢复报告。
6. 恢复剩余有效时长；不按现实离线时间推进订单、短控、保护或Q。
7. 从实体/站点快照重建合同投影，与存档进度比对；不重放经济事件。
8. 恢复表现与UI，解除加载暂停。按住中的猫/原目标必须同时存在且同ID；否则走明确恢复策略，不生成新目标。

临时交互提案：不保存半完成持有动作的进度；保存时取消到事务前稳定状态，读档明确显示动作已取消。已完成调查/作业永远保留。AI可恢复到等价稳定状态，但不能延长短控/吠叫冷却或改变目标归属。

### 5.4 内容版本与迁移要求

- `schemaVersion`只在保存结构变更时增加；`contentVersion`表示可用ID与场景节点；`balanceVersion`表示数值；三者不可混成一个应用版本。
- 保存当前合同的关键运行初值快照或保证对应配置仍可装载，避免读档后3只预算变4只、60%变80%。
- 物种近缘替换保留稳定业务ID或提供显式映射；旧图鉴、交易终结、合同引用及本地化必须一起迁移。
- 删除/重命名节点需要替代合法节点映射；不能把动物恢复到墙中，不能用默认原点代替未知节点。
- 已确认允许整档回滚；旧档中的交易/星/余额随同一快照恢复。同一快照再次进入菜单、恢复及重试仍必须幂等；不建立跨旧档不可回滚全局账本。

### 6.1 必须阻止进入构建的错误

1. 重复ID、缺失外键、禁用ID被启用内容引用、ID大小写混用、文本key缺中文或英文。
2. 图鉴总数与启用物种不一致；伙伴被错误算成目标；E06三尺寸被平台数和SKU数重复相加。
3. 合同目标预算小于所需数量，含未来无激活条件预算；星要求动物/线索/可回收物没有保底生成。
4. 指定活捉对象无兼容容器、无至少一套可获得/借用方案，或被猫Kill过滤遗漏。
5. 允许驱离却无可达边界；不允许驱出地图的必需对象连接场外删除节点。
6. 已生成目标在封堵后无任何可达处理节点/恢复节点；笼入口几何与物种体型不匹配；白天实例化可活动鼠，与夜间出现规则冲突。
7. 合同资产权重为负或总和为0；初始基准不是固定快照；80%比较写成`>`而非`>=`。
8. 同一合同不是恰好3个不同starId；星的失败被配置为隐含主任务失败。
9. 一个工具没有匹配补给、内部装填来源或无效目标反馈；装填/返车/读档设成免费补满。
10. 活体/满小笼可堆叠、P09袋与尸体重复占位、网袋无唯一绑定，或交易后重复返笼。
11. 同一活体既给现金又给捐赠经验；尸体捐赠开关为真；指定客户交付对象可售捐。
12. 必需伙伴自动行为被合同硬规则禁止且无替代方案；公开静默规则未包含犬吠却隐形判违约；限时/保护合同开启保货主动撤退。
13. 伙伴可受伤、阻玩家/射线、触发装置或占野生动物车位，与已定规则冲突。
14. 动画引用缺猫按住/松开/狗吠等必要状态；资产缺许可字段却被标记可发行。

警告而非硬错误：价格/时长超建议区间、车辆往返过长、物种相似资产复用过多、英文文本可能截断、性能预算未实测。合法但不好玩的初值需要游玩评审，不能仅凭schema通过宣称体验合格。

## 7. L01/Q01灰盒节点与尺寸提案

### 7.1 尺度和通行基准

以下为可直接搭建第一轮灰盒的提案，不是已测量的场地。坐标采用Unity米制，地面Y=0，平面X向东/Z向北。玩家几何先按高1.8m、半径0.3m测试；实际控制器确定后回归所有门、笼口和交互范围。

- 建筑净尺寸建议14m×10m，高2.8m；厨房5m×4.5m、储物间4.5m×4.5m、走廊净宽1.6m、入口/交接区4m×3m。
- 普通门净宽1.0m、高2.1m；主搬运路线净宽至少1.2m，转角留1.5m×1.5m。P1扩展前预留中/大型货物1.5m通道及2m转身区。
- 后院约14m×12m；主通路宽1.5m；灌丛/菜地提供可读遮挡，不把稀有塞进不可点击深处。
- 可部署小笼工作面至少0.8m×0.6m，笼口前留0.8m直线接近区；用真实模型尺寸再次测通路，不通过缩小碰撞体作弊。
- 固定车辆到主作业点的实际单程步行目标15—35s。若步行4m/s，对应约60—140m路径；住宅小场地需用入口/前院距离实现，不能把1m当5m。建议先取60—70m最远工作路线测试。
- 不为了满足时长把每个小点拉远。记录典型“拿工具—作业—回车”的总耗时和往返次数，再调停车距离与4格体验。

## 9. 性能、调试与首轮技术验证

- 先以GTX1660 6GB、1080p目标机建立L01灰盒基线，记录CPU主线程/GPU帧耗、显存/内存、GC、加载/保存耗时和最低帧段，不能只报平均帧率。

- 调试面板仅开发构建显示：runId/seed/configVersion、实体ID/状态/归属/合同角色、AI当前刺激/路径节点、伙伴租约、容器占用、账本命令ID。玩家产品UI保留可理解的状态与原因，不暴露内部字段。
