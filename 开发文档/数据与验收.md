版本：P0-data-0.3。配套[主规格](开发主规格.md)与[P0配置清单](P0_Config_0.3.json)。本文是目标数据契约；现有Demo使用简化DTO，差异见实施记录，不假定目标字段全部已接入。配置JSON用于后续生成/核对Unity静态资产，不可直接宣称已导入。

## 1. 标识、单位与目录

定义ID复用策划：I01–I14、M01–M17、S01–S02、C01–C12、E01–E18、P01–P10、H01/H02、L01–L06、Q01–Q18。派生物品ID为E06.Small/Medium/Large。每个运行实例另有GUID，不能拿speciesId或Prefab名当个体ID。场景固定点用L01.W01、L01.F01等稳定作者ID。

单位：距离m、速度m/s、持续时间s、角度deg、货币整数元、经验整数点、生命/耐久非负整数、比例0–1。时长统一有效游戏秒；保存时长剩余值或逻辑tick，不能保存Time.time绝对值再跨会话相减。累计tick为int64，模拟步长0.05秒（20Hz），动画/镜头插值逐帧。配置浮点拒绝NaN/Infinity，金额计算尸体价用整数除4。

建议工程目录：`Assets/Game/{Runtime,Editor,Tests,Scenes,Data,Prefabs,Art,Audio,UI,Localization}`；外部原始包放`Assets/ThirdParty/<作者或包名>`，不直接改源包运行代码。项目自制变体放Game，资产台账保留派生关系。纯领域程序集`RatControl.Domain`不引用UnityEditor；Runtime、Editor、Tests各自asmdef，Editor不进构建。P0不用Addressables，之后因实测内存需要再引入。

## 3. 运行状态与事务

### 3.1 实体结构

```text
AnimalState {
  entityId, definitionId, originRunId, activeRunId?, revision,
  role: RequiredTarget | OptionalPest | Rare | NonTarget | Livestock,
  life: Alive | Dead,
  control: Free | Stunned | Pinned | Contained,
  location: WorldPose | ContainerId | VehicleSlot | CompanyHolding | Terminal,
  terminalReason: null | Sold | Donated | Delivered | EmployerAccepted | CompanyReleased | LostOnFailure,
  investigated, discovered, uniqueCaptureRecorded, killRecorded,
  behaviorState, routeNodeId, timers, alertness, ownerClaimId?, rngState
}
```

现场释放是Contained→Free+WorldPose，保留ID；公司释放是Terminal，公司没有可刷收益的放生区。Dead不能Donated，Terminal不能再伤害/转移/调查。Pinned不计主任务稳定控制；Contained暂停自主伤害和移动。普通尸体调查与Rare活体调查按模式判断，不按当前UI选中的标签猜测。公司未售货物归profile.cargoAnimals/cargoItems所有，originRunId仅为来源；成功/保货终止时先将动物、容器、袋迁入公司表，再卸载run。新委托失败只清除本次待回程动物货物，不清除已在公司存放的旧货。

ItemInstance保存instanceId、definitionId、revision、ownerLocation、condition(0–100)、charges、loadedAmmo、loanOwnerId?、contentAnimalId?、upgradeIds[]。容器contents与动物location双向引用必须一致；库存中只有容器一个占位，动物不额外生成“活体物品”。小型鼠尸货物保存animalId，不强制bagInstanceId，carryKind=Corpse；活笼为OccupiedCage，不能相互部署。中大型BodyCargo可另绑定bagInstanceId。

工具耐久归每个instanceId，E03/E04提交成功一次-10；E01喷洒量连续保存。Refill从手持包转实际缺量至所选工具，不能超填或跨工具共享。AreaClean保存中心、半径及实际清掉的pestIds，过滤墙/楼板和死亡状态，整轮只扣一次；样本记录在清除表现后仍可调查。

CompanyState保存playerPose、selectedMapId、selectedContractId、starterGranted、equipment实例、基地未装车物资、cargo与pendingTradeCages。现场配送到箱内使用未领取实例列表，背包满时不转出，不能用远程库存直接领取。CartLine保存itemId/quantity，Order保存orderId、lineItems、lockedPrices、total、destination(Counter/Truck/FieldCrate)、remainingSeconds、delivered与unclaimedItemIds。未付款购物车不算库存；成功付款才创建订单实例。所有未取货物保留，重复交付不新增实例。

Run保存workLayoutSeed、各workSite的anchorId/pose、上一布局签名、5个targetPlanId、rareElapsed/rareDelay/rareEvaluated/rareResult/rarePendingSafeSpawn、动物走停/诱饵试探/警戒/近期路线。读档恢复结果而非重抽。

### 3.2 命令与事件

命令封套：`commandId, actorId, runId?, expectedRevision, targetId, payload`。返回：`Accepted | AlreadyApplied | Rejected`、reasonCode、newRevision、readBack。相同commandId只应用一次；expectedRevision过旧返回STATE_CHANGED。P0领域写入在主线程单队列提交，不引入网络式多线程锁框架。

事件封套：`eventId, sequence, logicalTick, runId, entityId, sourceKind, sourceActorId, sourceToolId?, causedByCommandId, payload`。sourceKind包括Player/Trap/Cat/Dog/Environment/System。动画与UI不发“已经捕获”事实，只能请求命令；事件在成功提交后发送。

| 命令 | 原子修改 | 已提交事件 |
| --- | --- | --- |
| BeginNight | Flow阶段、准备星快照、5只计划激活标志、光照状态、自动保存点 | NightStarted |
| CompleteWork | 当前工具实例耐久/余量、workStage、场地表现、导航边、样本生成标志 | WorkCompleted / RouteChanged |
| ApplyHit | 命中/适配判定、弹量、生命、死亡记录、尸体位置、目标投影 | ToolUsed / AnimalDied |
| CloseTrap | 动物revision、控制/容器关系、笼门状态、唯一捕获统计 | AnimalContained |
| TransferAnimal | 原/目标容器、动物location、容量占位、返还笼的位置 | CargoTransferred |
| Investigate | 个体记录、物种图鉴记录、统计，不改变货物去向 | InvestigationCompleted |
| ReleaseInField | 容器清空、原ID动物重回合法位置、目标投影撤回 | AnimalReleased |
| FinalizeDeparture | 成败复核、挑战结果、动物/设备回程归属、奖励账本、借用归还、持久化 | RunFinalized |
| Sell/Donate | 个体终态、现金或XP、交易账本、持久化 | TransactionCommitted |
| ConfirmCart/DeliverOrder | 一次核价扣款、全部订单行与目的地；整单交付原实例，满包未取货保存 | OrderCreated / OrderDelivered |
| RefillTool/AddBait | 对应工具缺量或指定装置状态、手持包余量，失败不扣 | ToolRefilled / DeviceBaited |
| AreaClean | 同空间范围死亡虫ID、一次工具-10耐久、样本保留 | AreaCleaned |
| StageTrade/TakeBack | 交接笼与携带容器原实例、动物唯一归属 | CargoTransferred |

同一模拟步冲突：先接收已排队伤害与系统失败，再处理捕获/交互完成，最后离场。对象revision是最后防线：致死先提交只留尸体；稳定捕获先提交，后续命中被容器遮挡拒绝。失败已触发则离场不能覆盖成成功，系统失败自动清货不能被UI取消。

现金/奖励/交易使用候选状态快照：准备全部变更→验证不变量→写入完整快照并成功替换→发布内存状态及事件。写盘失败保留提交前状态、暂停交易、显示可重试原因；不出现加钱已成功但货物未移除的半完成状态。世界中普通移动无需每tick落盘；离场/买卖/捐赠/领取奖励为持久化边界。

### 3.3 必须保持的不变量

- 每只动物、每件工具只在一个location；没有Terminal动物还列在车里；不存在容器引用环。
- 5只Q01目标的计划ID集合固定。激活前后、释放再捕、转移、读档都不产生第6只主目标。
- 任务进度从目标状态查询得出，禁止独立`killCount++`再额外`captureCount++`拼成成功。
- 一只个体最多一次正式捕获统计、一次击杀统计、一次最终交易/交付；再捕操作另记，不发奖励。
- 占用容器、装袋尸体、已装车动物守恒；借物归还/货物丢失不可复制或永久销毁工具。
- 一个订单扣款一次、交付一次；离场改投公司只改deliveryOwner，不新建订单。
- 星以contractId+challengeId保存首次领取状态，失败不结算本局新星；公司图鉴不因失败回滚，整档回退是显式载入较早快照。

## 4. P0运行初值说明

初始现金300、背包4格。首次赠E01/E03/E04、E05×1、E06.Small×1及常驻E14；P01/P02/P07/P10各1包，实际放车内，不硬塞背包。starterGranted每档一次；工具和补给跨单保存。赠送工具初装0以教学实际补充，补给足额；每把E03/E04容量100、每次成功-10；P02/P10一包100点，P01一包满量5喷剂单位/20秒，P07一包5次，部分装填保留包内剩量。

价格：P01=25、P02=30、P07=20、P10=20；夹120、小笼750（已有首次赠送不影响追加购买等级），E03/E04追加价各200为工程初值。允许同类多把，地图同时小笼1/夹1；不把商店拥有量当部署量。Q01报酬150/120XP，首星每颗30/40XP；家具阈值60/80%，5个任务M01固定不补。普通活体舱4位，第5只可留便携笼随车或交雇主接管，禁止容量软锁。

范围清尸2m、同空间遮挡过滤；蟑螂每源2–4只；鼠走2–5秒停1–3秒；现场整单10秒，基地即时柜台/卡车二选一。C01夜间180–300秒后一次概率45%，仅室外；无安全点时保留判定结果等待安全点，不重新抽取。所有数值为首轮工程初值，试玩后调整。

只启用L01/Q01，其余展示实际策划名称和未开放；未定报酬展示策划区间，不使用参考图金额。P0额外商品定义P10清洁补充剂；E14常驻，P09保留历史/后续用途但不作为鼠尸前置。零现金必做补给差额救济需幂等，不重新发礼包或免费复制工具。

## 5. 存档格式与恢复

位置：`Application.persistentDataPath/Saves/<profileId>/`；3个独立档位（工程初值），每档一个当前委托手动档和最近自动档，设置单独保存。`schemaVersion`、`contentVersion`、`specVersion`是三个不同字段，不用产品显示版本判断迁移。

```text
SaveEnvelope {
  schemaVersion: 2, contentVersion: "P0_Config_0.3", specVersion: "P0-spec-0.3",
  profileId, saveId, parentSaveId?, savedAtUtc, payloadHash,
  profile: { totalXP, cash, unlockedContracts, equipment, skills,
    encyclopedia, earnedStars, rareEvents, starterGranted, selectedMapId, selectedContractId, cart, tradeHoldings, completedRunIds, transactionLedger,
    cargoAnimals, cargoItems },
  run?: { runId, seed, rngStreams, contractId, phase, logicalTick,
    targetPlans, animals, itemInstances, containers, workSites, assets,
    closedEdges, playerPose, vehicle, orders, investigations, challenges,
    qCooldownRemaining, stamina, breath, toolAmmo, companionStates },
  presentation: { trackedObjective, selectedSlot }, settingsVersion
}
```

动物与订单独立随机流保存内部状态，不能每次加载重新Random.InitState后从头抽。计划ID未激活也保存，避免NightStarted重复产生鼠。恢复顺序：校验封套/hash→迁移纯DTO→注册静态内容ID→创建全部实例→绑定容器/location/路线→恢复合同投影/计时器→创建表现→恢复暂停与输入。恢复时不重放发奖事件；HUD从当前快照读取。

保存点：公司出发前、入夜状态应用完成、每次合同结算（成功/失败/主动终止）、每次交易/捐赠/商店扣款；玩家可在当前委托主动手动保存。保存前取消未提交持续交互，短暂停世界复制DTO；保存不重置陷阱/内装弹量/Q/物流/伙伴claim。

落盘写临时文件、刷新、计算校验、在同目录替换正式文件并留bak；首次保存用原子重命名。遇坏档先读bak再提示恢复，未知未来schema拒绝覆盖；迁移先备份、逐版本纯函数转换并验证不变量，失败保留原档。不能删除未知ID装作修复：关键ID缺失阻止进入并列出内容版本，非关键旧表现ID可映射占位但不篡改货物。

允许显式读取较早手动档，钱/XP/星/货物/账本一起回滚，等价同一单机档位历史分支；绝不把旧现场与最新公司账本混读。已结算run的遗留快照不能作为“继续当前委托”自动恢复；用户选择旧档时整份快照恢复。退出时未存的游戏变化允许丢失，不偷偷发补偿奖励。

旧档迁移：先完整备份。旧3目标活动局按原ID保留并追加2个唯一计划；不要给已结算局补鼠/重发奖。旧布局和已判稀有结果优先恢复，未知值有明确版本策略。旧全局spray/repairs/cleaning仅分配到原工具实例一次，新增备件不得复制其余量；旧每单赠物迁到profile后设starterGranted，不重新赠。旧单件订单转一行整单，已付只迁未取货；旧尸体袋鼠尸转直接尸体，不能顺带新返笼/袋。旧夹多于1个保留为库存，限制仅部署；不得删除合法玩家备件。迁移幂等并记录来源schema。

## 6. 数据与场景自动校验

启动编辑器验证命令（项目自定义工具，非UnitySkills名称）应输出结构化错误列表：severity、definitionId、fieldPath、reason、suggestedFix。以下错误阻止接单/打包：重复ID、空本地化、引用不存在、目标无合法处理方法、无可达捕获点、关键通路关闭后断路、合同非3星、未知素材许可、缺失关键Prefab/Animator参数、存档模式不支持当前内容。

P0计数校验：5图鉴、1正式可玩合同、3星、M01主目标5、核心定义11（E14常驻）/测试额外2；M02附加不改主目标总数。检测所有definitionId/sceneObjectId和主规格坐标表可绑定，目标场景在Build Settings内；TestRange只能Development构建访问。

几何检查需至少三态：两个F都开/只封一个/全封。每态验证鼠外部路径及室内已入鼠可到捕获位；验证玩家、便携笼和未来手持大货不是只验证NavMesh中心点。完整6图计数与45条覆盖属于P2验证，不在P0虚报通过。

## 7. 可重复验收

测试输出记录buildId、configVersion、seed、开始档位、实际步骤、期望/实际、截图或事件日志、Pass/Fail。下列是开发后的验收计划，当前新版本用例均待本轮实现后执行；旧版证据仅覆盖旧版，不沿用Pass。EditMode集中于领域守恒/阈值/存档迁移；PlayMode检查交互与场景；构建人工试玩检查手感、渲染、声音和语言。不要用测试直接给目标判完成来冒充游玩闭环。

## 8. Windows构建交付

P0先Windows x86_64独立包，包含exe、Data和必要运行库，不要求Steam登录。保留Development诊断版与Release候选，测试使用构建不只Editor Play。输出BuildInfo（引擎/包/提交/配置/时间）、变更摘要、已知问题与验收记录；首次运行设置和存档目录可写，卸载/覆盖程序不删除用户档。

构建前：配置/引用/许可校验、编译无错、核心领域测试通过；构建后：干净用户目录首次启动→新档到结算→退出重开继续→切换中英/分辨率/重绑→旧档升级/坏档恢复。禁止把Editor API、开发测试入口和来源不明参考图片打进Release。未来Steam只预留profileId/存档路径与可替换PlatformService，不预先接云存档或成就空实现。
